## On-device dictation (iOS 26 SpeechAnalyzer) - (16:00)

**Status**: ✅ Working — stop→transcript 728 ms vs 2683 ms cloud

Cloud STT (gpt-4o-mini-transcribe, 913 ms) was the fattest stage after parse. Replaced
with on-device transcription of the recorded m4a after the stop tap, transcript sent to
the creation job, audio never uploaded on the hot path. Codex caught: what the user tested
is `DictationTranscriber` (system dictation model), not `SpeechTranscriber` — module
supports both; reconcile refused jobs without audio; route on an explicit `sttSource`.

Three parallel Opus agents:
- **Native** `plugins/ios-src/VRSpeech.swift` + `.m`, `plugins/withVRSpeech.js`,
  `lib/vrSpeech.ts` contract: `status/prepare/transcribeFile/cancel`, engines
  `dictation|transcriber`, assets via `AssetInventory.assetInstallationRequest`. No
  speech permission needed (SpeechAnalyzer ≠ SFSpeechRecognizer).
- **Backend** `creationJobs.begin` takes `transcript + sttSource:"device"` (exactly one of
  audio/transcript), worker skips STT, `deviceSttMs/Engine/Locale` in perf; retry flips
  to cloud when replacement audio arrives.
- **Client** `lib/deviceStt.ts` (`runDeviceStt`: status → race vs 4 s timeout → cancel;
  `runVoiceHandoff`), warm-up `speechPrepare` at record start + launch, reconcile rebegins
  from the persisted transcript, Settings "Voice language" (auto/en/ar) + dev-only
  "Voice engine" row, `[VR PERF] device_stt` / `device_stt_fallback`.

Build 3 failed on `installedLocales` being `{ get async }`; build 4 compiled. Fridge take
on device: `sttSource=device deviceStt=555ms`, parse 2114 ms, card at 4255 ms (cloud run
same morning: 5300 ms). Parse is now half the total — next target.
