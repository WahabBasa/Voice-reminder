## Ring state: card went Overdue the instant a ring started - (14:00)

**Status**: ⚠️ Built (dev build on device 09-11), first device pass 09-12 green

User report: card flips red the moment it rings, stays red after Later, only updates
minutes later; banner X (Apple's Stop) leaves it overdue. Codex investigation (high):
card derives Overdue purely from `now > due`, no ringing input; Later writes a native log
JS only drains on foreground, on a different clock from the 30 s card tick, and never
from the tick; Later recorded "tap+5" but armed "original+5"; Stop already = Done, just
never propagated; nothing observes `alarmUpdates`, the 180 s timeout was an assumption.

Decisions: no red while unresolved; Later = 5 min from the tap, unlimited, new chain each
time (ignored-ring cap of 3 stays); Done finishes THAT occurrence only; Missed only after
the chain is exhausted. Three parallel Opus agents on frozen contracts:
- **L** `lib/ringLifecycle.ts` (per-occurrence record: ringing/snoozed/done/missed,
  chainId, eventId de-dup, terminal states), `remindersMembership.ts` ("Ringing now",
  "Rings again", "Missed · t", "Due now" during the 16-min unknown grace; repeaters held
  on the ringing occurrence), per-occurrence completion via history `scheduledFor`
- **N** `VRAlarmIntents.swift` / `withAlarmKit.js`: alarm metadata (reminderId,
  occurrenceAt, chainId, chainStep), Snooze awaits registration then records the real
  time, event log peek/ack with UUIDs, `getAlarmStates()`, `stopOccurrence()`,
  `alarmUpdates` observer → `VRAlarmEvent` hint via an ObjC `RCTEventEmitter`
- **R** `lib/ringReconcile.ts` sole drainer (peek → lifecycle + legacy ledger → ack;
  launch/foreground/tick/native), `lib/occurrenceActions.ts` `completeOccurrence` /
  `laterOccurrence` used by card, overlay, alarm screen, fallback actions

Build failures on the way: Swift `RCTEventEmitter` subclass can't see React headers
(moved to ObjC), duplicate `setMeta/clearMeta`, `AlarmManager.shared.alarms` is a
throwing getter, and a backtick in a Swift comment inside the JS template literal killed
`expo config` (memory: alarmkit-plugin-template-literal).
