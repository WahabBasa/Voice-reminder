## Performance optimizations applied - (20:25 on Jan 3 → 08:04)

Received detailed performance reports identifying JS thread blocking as the root cause of tap lag. Applied several optimizations:

### A. Sort optimization in `index.tsx`

Pre-compute timestamps before sorting to avoid O(n log n) Date constructions:

- `remindersBySection` (line 464): now uses `filteredReminders.map(r => ({ reminder: r, ts: new Date(r.createdAt).getTime() }))` then sorts by `ts`
- `completedBySection` (line 485): same pattern for history entries
- `completedTodayReminderIds`: uses numeric timestamp bounds instead of `toDateString()` string comparison

### B. Locale formatting cache in `time.ts`

Added LRU caches (100 entries each) for expensive `toLocale*` calls:
- `cachedTimeString()` - caches `toLocaleTimeString`
- `cachedWeekdayString()` - caches weekday formatting
- `cachedShortDateString()` - caches short date formatting

### C. Load yielding in `index.tsx`

Changed `loadData()` to load reminders first, then defer history load via `InteractionManager.runAfterInteractions()` so taps can interleave.

### D. Slider gesture fix attempt

Added responder capture to slider containers in `edit.tsx` and `DetailSheet.tsx`:
```tsx
onStartShouldSetResponder={() => true}
onMoveShouldSetResponder={() => true}
onStartShouldSetResponderCapture={() => true}
onMoveShouldSetResponderCapture={() => true}
```

Removed the `NativeViewGestureHandler` wrapper that wasn't working.

**Result**: These optimizations reduced some JS work but **did not fix the double-tap issue**.

## Performance instrumentation for tap → edit sheet delay - (08:04)

**Status**: 🟡 Instrumented + ready to repro

Since optimizations alone didn't fix the issue, added comprehensive perf tracing to diagnose exactly where the delay occurs.

### What's instrumented:

**A. Home screen tap tracing (`index.tsx`)**
- `tapDebugSnapshotRef` captures state at tap time (reminders count, history count, isLoading, etc.)
- `recordReminderPressIn()` logs `reminder_press_in` with traceId
- `handleReminderPress()` logs `reminder_press` and `router_push_edit`, passes traceId to edit screen

**B. JS stall monitor (`lib/perf.ts`)**
- `requestAnimationFrame` loop detects when event loop stalls > 100ms
- Correlates stalls with last tap traceId
- Enable with `EXPO_PUBLIC_VR_STALL_MONITOR=1`

**C. Storage timing (`lib/storage.ts`)**
- `getReminders()` and `getHistory()` log:
  - `getItem_start`, `getItem_done` (with ms duration)
  - `parse_start`, `parse_done` (with ms duration, byte count, item count)

**D. Edit screen lifecycle (`app/reminder/edit.tsx`)**
- `screen_mount` - when component mounts
- `screen_first_frame` - first requestAnimationFrame after mount
- `runAfterInteractions_scheduled` / `_start`
- `loadReminder_start` / `_reminders_loaded` / `_done`
- `audio_preload_scheduled` / `_start` / `_done`
- `bottomSheet_onAnimate` / `_onChange`

### How to run:

```powershell
# Enable perf logs
$env:EXPO_PUBLIC_VR_PERF_LOGS="1"

# Enable stall monitor (optional)
$env:EXPO_PUBLIC_VR_STALL_MONITOR="1"

# Start Metro (port 8082 if 8081 is occupied)
npx.cmd expo start --clear --port 8082
```
