## Performance instrumentation for tap → edit sheet delay - (08:04)

**Status**: 🟡 Instrumented + ready to repro

Tap-to-edit is still slow / sometimes feels like it needs 2 taps, so I added correlated perf logs to pinpoint where the delay happens (before `onPress`, during navigation, or during edit sheet mount).

Changes:
- Added tap trace logging on Home: logs `reminder_press_in` and `router_push_edit`, and passes a `traceId` into the edit route for correlation.
- Added edit screen lifecycle logs: mount/first frame, `runAfterInteractions`, bottom sheet `onAnimate`/`onChange`, reminder load timings, and audio preload timings.
- Added storage timing logs for AsyncStorage `getItem` and `JSON.parse` to catch stalls from large JSON blobs.
- Added a JS stall monitor (optional) to detect event-loop stalls and attribute them to the most recent tap trace.

How to run:
- Set `EXPO_PUBLIC_VR_PERF_LOGS=1` to enable perf logs.
- Set `EXPO_PUBLIC_VR_STALL_MONITOR=1` to enable JS stall monitor logs.
- Start Metro (used `--port 8082` because `8081` was already occupied): `npx.cmd expo start --clear --port 8082`

Files:
- `app/index.tsx` - tap tracing + history loading scheduling
- `app/reminder/edit.tsx` - edit screen + bottom sheet trace logging
- `lib/storage.ts` - AsyncStorage + parse timing logs
- `lib/perf.ts` - stall monitor + tap attribution helpers
- `lib/time.ts` - cached locale formatting helpers
- `components/DetailSheet.tsx` - slider responder capture attempt (still needs validation)
