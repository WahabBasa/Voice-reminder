## Fixed plugin-generated Kotlin compilation + confirmed "alarm-only" UI path - (15:55)

**Status**: ƒo. `expo prebuild --clean` + `expo run:android` succeeded; alarms render via `AlarmActivity`/`AlarmRoot` and only show alarm UI

### What happened

After the earlier alarm work landed, a follow-up build hit Kotlin compilation issues inside the **plugin-generated** native modules (these get written during `expo prebuild`, and the `/android` folder is treated as generated/ignored in this repo).

So the fix needed to be applied to the **config plugin templates**, not by manually editing `android/app/src/...` files.

### Fixes applied (plugin templates)

1) **Fix `ActivityControlModule` current activity access**

The generated Kotlin was referencing `currentActivity` directly in a `ReactContextBaseJavaModule`, which is not available in that scope. Updated to use `reactContext.currentActivity`.

- `plugins/withAlarmAudioModule.js:221` - `ACTIVITY_CONTROL_MODULE_KT` template
- Updated references:
  - `plugins/withAlarmAudioModule.js:250` - `getCurrentActivityName()`
  - `plugins/withAlarmAudioModule.js:262` - `isAlarmActivity()`
  - `plugins/withAlarmAudioModule.js:298` - `finishIfAlarmActivity()`
  - `plugins/withAlarmAudioModule.js:338` - `finishCurrentTask()`
  - `plugins/withAlarmAudioModule.js:378` - `logAppTaskState()` (the task/state dump helper)

2) **Fix `AlarmActivity.onNewIntent` override compatibility**

The generated `AlarmActivity.kt` had `onNewIntent(intent: Intent?)`, which can trip override/signature issues on newer Android toolchains. Updated the template to use `Intent` and added a suppression annotation so it compiles cleanly.

- `plugins/withFullScreenAlarm.js:172` - added `@Suppress("OVERRIDE_DEPRECATION")`
- `plugins/withFullScreenAlarm.js:173` - `override fun onNewIntent(intent: android.content.Intent)`
