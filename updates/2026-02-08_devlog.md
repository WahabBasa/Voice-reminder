## Clarified alarm launch + added full logging pipeline - (09:30)

**Status**: ✅ Implemented primary AlarmActivity path + in-app overlay fallback; needs on-device validation

Goal was to make the alarm behavior unambiguous and stop the “alarm screen shows, then the rest of the app UI is visible underneath after dismiss/snooze” issue.

### What changed (high level)

- **Primary alarm UI path (lockscreen/background):** Notifee full-screen intent ➜ `AlarmActivity` ➜ RN root `"alarm"` ➜ `alarm/AlarmRoot.tsx` ➜ `AlarmOverlay`
- **Fallback path (foreground app):** `app/_layout.tsx` polls pending alarm and renders `AlarmOverlay` on top of current UI **without navigation**
- **/alarm route is debug-only** now (no production routing via expo-router or Linking)
- Added structured logs + a native task/activity dump so we can confirm *exactly* which Activity and RN root is active from a single `adb logcat`

### Key implementation details

- `app/_layout.tsx:97` - `AlarmOverlayFallback()` (MainActivity fallback overlay; resolves by clearing pending + stopping audio + hiding overlay; no `exitApp`/finish)
