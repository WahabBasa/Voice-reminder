# Devlog - 2026-10-08

## ASO round: market research, new screenshots, A/B test submitted - (09:45)

**Status**: ✅ PPO test submitted to Apple (WAITING_FOR_REVIEW). No app code changed, no build, no Convex push.

Spent the session on ASO for Remi rather than the app itself.

**Research (all saved under `docs/aso/`):**
- Mined Google Play reviews of the biggest "talking alarm" apps (`docs/aso/competitors/talking-alarm/report.md`, pipeline in `scripts/`). Talking Alarm Clock Beyond: 51,350 reviews; ZipoApps: 15,674. Google ignores the country param, so country is inferred from language. Takeaways: #1 complaint is "the alarm didn't ring" (Android killing the app), #2 ads; #1 praise in ja/ko is "it tells me what the alarm is for"; Arabic users ask for an Arabic voice. The CSVs (~9.5 MB) are left untracked; `fetch.py` regenerates them.
- Country selection (`docs/aso/research/country-selection-2026-10.md`): Brazil is the best cheap+wide+pays market. Batch picked: Brazil (pt-BR), Mexico (es-MX), Saudi/UAE (ar-SA), Korea, Japan.
- What people keep forgetting (survey-backed): pills (64% of missed doses), appointments (36-42% of no-shows), bills (35% of late payers), parents' birthdays. Those became the screenshot examples.

**Screenshots:** the old renders had long serif headlines and unreadable subtitles. A headline-swap pass (`marketing/retitle.py` -> `renders_v2/`) got rejected. Then generated a new set with OpenRouter `openai/gpt-5.4-image-2` at 2K 9:16 through the PTC keyring (`marketing/gen_or_shots.py`, run with `ptc run --timeout 900 gen_or_shots.py`, `SLOTS=`/`SIZE=` env vars; `ptc run` doesn't pass argv and its default timeout is 120 s). GPT tops out at 2K (4K = HTTP 400). About $0.29 per 2K shot. Output in `marketing/renders_v3/` (7 shots). Fixed wrong weekday/date pairs and a hallucinated bubble ("I've got this for you") along the way.

**Claims checked against code:**
- Remi does NOT say the clock time. `SPOKEN_LINE_RULE` (`convex/helpers.ts:249-279`, OLD-95/104) bans it on purpose. Adding "It's 8:00 am." can't be server-only: the device plays one `reminder_<id>.wav` for every ring, nag and native snooze (`lib/alarmSounds.ts:37`, `plugins/withAlarmKit.js:662` VRSnoozeIntent), so a snooze would replay a stale time. A correct fix needs Convex + JS + a native build (separate first-ring wav, time-less snooze sound, regenerate audio on time-only edits, 12/24h from the device). Parked, so screenshot #1 "Says the time. And what to do." is held back.
- "Even on silent" is true on iOS 26+ (AlarmKit); user confirmed it works, claim kept.
