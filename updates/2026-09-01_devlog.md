## Creation pipeline rework: instant card + creation jobs - (08:30-14:45)

**Status**: ✅ Implemented, all gates green; deploy (convex --once + OTA) running at wrap-up

"App should have almost immediate reminder creation." Mapped the chain first: micStop→card
7.3s = 1.5s upload + 5.6s action (whisper + parse), and the overlay blocks until the whole
round trip returns — the row exists in the store before the user is allowed to see it. That's
why OLD-106's prompt-trimming measured nothing: the pipeline was on the user's clock.

The shape that shipped (spec: `docs/specs/2026-09-01-creation-pipeline-p0p1.md`, survived 4
Codex rounds + post-impl reviews):

- **Server**: `creationJobs` table + mutation-first workflow — begin/commit/cancel/retry/ack,
  generation-token CAS on every write, sweep cron, strict job-only validator
  (`creationValidate.ts`, reject-never-repair). Worker split into `creationJobActions.ts`
  ("use node" can't hold mutations). Legacy actions untouched except 25 additive lines of
  explicit-date/time provenance in `buildReminderPlan`. 63 race tests on convex-test in a
  **new vitest lane** (`npm.cmd run test:convex`) — convex-test is ESM-only, jest can't load it.
- **Client**: PendingTake outbox + card above Today (setting-up → transcript → rows → armed),
  `watchQuery` subscriptions (hydration's 1s polling replaced too), serialized `commitTake`
  under a store creation lock, 30-cell reconcile dispatch table, startup/foreground recovery —
  which also closes a hole legacy always had: killed app mid-creation = server row but no local
  alarm, ever.
- **P0**: recording preset stereo 44.1k/128k → mono 16k/64k (upload ~4x smaller), batched
  server writes, `storage.get` finally measured.
- **Review catches that mattered**: zero-kept takes vanished silently (cap/premium surfaces
  restored); "today at 3" said at 3:30pm perma-failed the take with retries burning on the same
  instant (explicit-dated one-offs now create as Overdue, like legacy); sweep GC spent its
