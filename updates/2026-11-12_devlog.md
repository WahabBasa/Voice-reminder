## Continued: Canal Log hardening, feature folders, paged data, one-row header - (12 Nov 13:55)

**Status**: ✅ All live on the website and API. Committed in `C:\Dev\canal-log`, local only (no remote).

Started from "why do I see Server waking up every time I come back" and "can this take 1,000 to 2,000 people". Five rounds, each built by Opus 5.5 medium agents and deployed on an explicit go.

- **Security.** PIN lockout (5 wrong = 15 min, 429 + Retry-After), rate limits (login 10/min per IP, 300/min per person, `/health` exempt), caps (update text 4,000, batch 100, body 1 MB), a deactivated person loses access within 60 s, the demo seed is blocked unless `ALLOW_DEMO_SEED`, HSTS. `People` got `FailedPins` + `LockedUntil`.
- **Hosting.** SQL moved from the free serverless tier to Basic (2 GB, no auto-pause, about $5 a month). `az sql db update` needed `--use-free-limit false`. The `free-tiers-only` policy now allows SQL Basic; the user ran that policy command himself, the classifier blocks me from loosening it. Budget raised to $10 in the portal. `api/Data/KeepAlive.cs` pings its own `/health` every 10 min so the F1 plan stays loaded.
- **Feature folders.** `web/src` is now `app/`, `features/{codes,updates,people,auth}`, `shared/`. `eslint-plugin-boundaries` runs inside `npm.cmd run build`, so a wrong import fails the build. The rules are in `ARCHITECTURE.md`. 16 of 16 before/after screenshots matched.
- **Data.** The real cause of "waking up": the site showed that label on any request over 3.5 s, and Updates pulled whole tables. Now `/log/page` is keyset-paged with filters in SQL, `/log/facets`, a server cache with ETag/304 for `/tracker`, `/people`, `/codes`, Brotli, 7 indexes, and `/export.xlsx` built on the server from the filters picked. Tracker payload 335 KB → 18 KB. Updates opens unfiltered, newest first (the "Date: Today" chip is gone, owner rule).
- **Header.** One row per page: name, tabs or search, Filter and "…" on the right. Content starts 60 to 106 px higher at 1366x768. Trend lost its "170 made" count because it pushed the week arrows around. Follow-ups: a divider after "Canal codes", Date column 100 → 114 px.
