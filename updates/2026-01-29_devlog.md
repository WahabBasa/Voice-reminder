# Devlog - 2026-01-29

## Lock-screen friendly alarm + background delivery fallback - (06:14)

**Status**: ✅ Implemented

Implemented a lock-screen friendly alarm path and a fallback for background delivery so the alarm UI can surface even when the reminder fires while the app is backgrounded.

### What changed:

**Pending alarm persistence & recovery (`index.ts`, `lib/notifications.ts`)**
- Added `setPendingAlarm()`, `getPendingAlarm()`, `markPendingAlarmHandled()`, `clearPendingAlarm()` helpers with AsyncStorage persistence
- `index.ts` now listens for `AppState.change` — when app becomes active, it checks for any unhandled pending alarm and navigates to `/alarm`
- Startup also runs `maybeNavigateToPendingAlarm()` in case initial notification path was missed
- This ensures background-delivered alarms don't get lost

**Clear pending alarms on dismiss/snooze (`app/alarm.tsx`, `lib/notifications.ts`)**
- `handleNotificationEvent()` now clears pending alarm on `DISMISSED` and `ACTION_PRESS` events
- Prevents repeated alarm UI launches after user dismisses or snoozes

**Full-screen intent hardening (`lib/notifications.ts`)**
- Changed channel importance from `HIGH` → `MAX`
- Added `visibility: AndroidVisibility.PUBLIC` for lock screen display
- Added explicit `launchActivity: "default"` to both `pressAction` and `fullScreenAction`
- Snooze rescheduling now also includes full-screen action config

**Native activity flags** (`android/app/src/main/java/.../MainActivity.kt`)
- Activity can now show over lock screen and wake the device (requires rebuild)

### Files touched:
- `index.ts:1-125` - AppState listener, pending alarm check, dedup guard
- `lib/notifications.ts:1-600` - Pending alarm storage, MAX importance, visibility, launchActivity
- `app/alarm.tsx` - Dismiss/snooze clears pending alarm
- `app/paywall.tsx`, `app/settings.tsx` - Minor related changes

### Notes:
