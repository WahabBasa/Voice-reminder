### Critical Issues Discovered During Testing - (19:54 - 20:00)

#### Issue #1: Snooze Crash

**Error**:
```
TypeError: Cannot read property 'split' of undefined
Call Stack:
  getNextTriggerTime (lib\time.ts)
  handleNotificationEvent (lib\notifications.ts)
```

**Root Cause**: When snooze notification fires, `data.days` is `undefined` because snooze notifications don't preserve the original reminder's `days` field. The `getNextTriggerTime` function tries to call `.split()` on undefined.

**Impact**: App crashes when trying to reschedule after snooze, reminder gets lost.

**Status**: ❌ Not fixed yet - needs null check in `lib/time.ts`

#### Issue #2: Alarm Audio Still Silent

**Symptoms**:
- Logs show: `✅ Playing via react-native-sound`
- VolumeManager sets alarm volume to 0.9
- Audio file exists and loads successfully
- But **NO SOUND** plays - only vibration

**Investigation Findings**:

Terminal logs confirm playback sequence:
```
[AudioService] Set alarm volume to 0.9
[AudioService] ✅ Playing via react-native-sound
[VR] ✅ Alarm audio playing via AudioService
```

**Current Hypothesis**: 
We're setting the **ALARM volume stream** via VolumeManager, but `react-native-sound` might be playing through the **MUSIC audio stream**. These are separate:
- `VolumeManager.setVolume(0.9, { type: "alarm" })` - Sets alarm stream volume
- BUT `react-native-sound` playback might default to MUSIC stream

**What Controls Audio Stream in react-native-sound**:
- On Android, audio stream is controlled by `AudioAttributes.USAGE_*` flags
- react-native-sound likely uses `USAGE_MEDIA` (music stream) by default
- We need `USAGE_ALARM` to output to alarm stream

**Possible Solutions**:
1. Check if react-native-sound exposes AudioAttributes configuration
2. Use native Android MediaPlayer with alarm stream in a custom native module
3. Keep using MUSIC stream but set MUSIC volume (not ALARM volume)

**Next Steps**:
- [ ] Check react-native-sound documentation for audio stream configuration
- [ ] Test with MUSIC stream volume instead of ALARM stream
- [ ] Consider native module for true alarm audio if react-native-sound can't do it
