## Mic did nothing: the 16 kHz preset failed prepare - (12:50-13:50)

**Status**: ✅ Fixed, OTA group 44639e60 live

Mic tap didn't auto-start, record button did nothing, no crash. `pymobiledevice3 syslog live`
over USB (works on Windows, `PYTHONIOENCODING=utf-8`) showed it on every attempt:

```
AudioQueueNew: ->AudioQueueNewInput  1 ch,  16000 Hz, aac
AudioQueueStop: ->... immediate           (13 ms later, buffer count = 0)
AudioQueueDispose
```

AVAudioRecorder rejected the 09-01 preset (AAC 16 kHz mono **64 kbps**). expo-av passes the
settings straight through (no clamping, contrary to the preset's comment) and rejects
`createAsync` with `E_AUDIO_RECORDERNOTCREATED`; `RecordingOverlay` awaited it with no catch, so
the sheet sat idle and Sentry never heard. The preset test only pinned literals against a mock.

Codex (gpt-6-astra) couldn't find an authoritative Apple bitrate table for 16 kHz mono, so the
fix keeps the size win but makes it safe:

- `lib/recordingPreset.ts` — iOS bitRate 32000 (≈75% fewer bytes than HIGH_QUALITY); exports
  `RECORDING_FALLBACK_PRESET` (= HIGH_QUALITY)
- `lib/audio.ts:133` — any `createAsync` rejection → Sentry breadcrumb + perfLog `preset_failed`,
  one retry with HIGH_QUALITY, then rethrow
- `components/RecordingOverlay.tsx:298` — start path in try/catch; "Couldn't start the
  microphone. Tap to try again." retryable state
- `__tests__/lib/audio.test.ts` new (fallback, double-fail, no retry on audio-mode error)

Gates: tsc clean, 46 suites / 1405 tests. Commit `0a03f30`. Published from the agent shell via the
PowerShell-spawn form (the `.cmd` wrapper form is classifier-denied in auto mode); verified
delivery by curling `https://u.expo.dev/<projectId>` with the expo headers — production manifest
now serves `01a07b45…`. Device check after two relaunches: recording works. Whether 32 kbps is
honoured or the fallback fires is visible in the syslog (16 kHz queue started vs disposed then a
