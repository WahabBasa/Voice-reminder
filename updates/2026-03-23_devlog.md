# Devlog - 2026-03-23

## Production readiness audit + 5 bug fixes - (18:58)

**Status**: All fixes applied, tsc clean, app running on device

Did a full codebase review looking for things that would bite us in production. Cross-validated findings with another agent's critique, which caught a few real bugs I'd initially dismissed. Ended up with 5 fixes:

**Fix 1 - Create flow false-success** (`app/reminder/new.tsx`)
The create screen was toasting "Reminder created" and navigating away *before* `scheduleReminder` ran (it was deferred inside `InteractionManager.runAfterInteractions`). If scheduling failed, user would think it worked but never get the alarm. Moved scheduling into the main try block so it's awaited before success feedback. Added `ExactAlarmPermissionError` handling in the outer catch.

**Fix 2 - Stale audio after regeneration** (`components/EditReminderSheet.tsx`)
`downloadReminderAudio` skips the download if `reminder_<id>.mp3` already exists locally. So when a user regenerated audio, the old file was still served. Added `deleteLocalAudio(reminder.id)` before `scheduleReminder` in `handleRegenerate`.

**Fix 3 - Edit schedule metadata drift** (`components/EditReminderSheet.tsx`)
Editing a reminder only updated legacy fields (`time`, `frequency`, `days`) but not canonical schedule fields (`scheduleType`, `onceAt`, `rrule`, `dtstart`, `tzid`). Startup sync trusts canonical fields, so edits would silently revert. Added `migrateLegacySchedule()` call in `handleSave`, bumped `schemaVersion` to 4.

**Fix 4 - ErrorBoundary** (`components/ErrorBoundary.tsx`, `app/_layout.tsx`, `alarm/AlarmRoot.tsx`)
Created a React class error boundary with retry. Wrapped `RootLayout` and `AlarmRoot` so crashes show a recoverable UI instead of a white screen.

**Fix 5 - Recording duration cap** (`components/RecordingOverlay.tsx`)
No max recording length meant users could record indefinitely. Added 2-minute auto-stop via useEffect watching `duration`.

**Fix 6 - RevenueCat error overlay** (`lib/purchases.ts`, `app/_layout.tsx`)
RevenueCat's `LOG_LEVEL.DEBUG` caused native ERROR-level logs that Expo's LogBox rendered as red overlays (especially on USB-only dev with no internet). Changed to `LOG_LEVEL.WARN` and added `LogBox.ignoreLogs` patterns for RevenueCat strings.
