## Alarm scheduling diagnostics + Android 12+ gate - (02:40)

**Status**: OK. Much clearer why alarms don’t fire on some devices

Did a pass on the “alarm not going off” issue. Main changes:

- Stopped trying to auto-open `/alarm` from `EventType.DELIVERED` (Android blocks background UI launches a lot of the time), and kept navigation only on notification press.
- Added cold-start routing: if the app was opened from a notification press, it now routes straight to `/alarm` on launch.
- Added an Android 12+ exact-alarm gate. If `Alarms & reminders` isn’t enabled, scheduling throws `ExactAlarmPermissionError` and the UI nudges you to diagnostics.
- Added an in-app “Alarm diagnostics” screen to inspect `notifee.getNotificationSettings()` + scheduled trigger IDs, with quick links to relevant system settings.
- Added audible fallback by setting channel `sound: "default"` so users notice delivery even if the alarm UI can’t open (channel immutability caveat still applies).

Heads-up / follow-up:
- Need to verify notification press routing when the app is backgrounded (not killed). If Android sends PRESS via background handler in that state, we may need to handle PRESS there too.
