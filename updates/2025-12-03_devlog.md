# Devlog - 2025-12-03

## Got Phase 1 working - (19:30)

**Status**: ✅ App running on phone

**Intent:** Get the basic Expo + Convex project set up with a simple two-screen UI. Just the skeleton - home screen showing reminders (empty for now) and a record screen with a mic button. Nothing functional yet, just the foundation.

**What I did:**

Kicked off with `create-expo-app` using the blank-typescript template. Added expo-router for navigation since we want tab-based UI. Connected Convex for the backend - ran `npx convex dev --once --configure=new --project voice-reminder` which set up a new project and gave us the dashboard at https://dashboard.convex.dev/d/proper-stoat-767.

For the UI, made a tabs layout with two screens:
- Home (`app/(tabs)/index.tsx`) - shows an empty state right now with a "Create Reminder" button that links to the record tab
- Record (`app/(tabs)/record.tsx`) - big mic button in the center, toggles between blue mic icon and red stop icon when you tap it. Added a "Tap to Record / Tap to Stop" label so it's clear what state you're in.

Wrapped the whole app in ConvexProvider in `app/_layout.tsx` so we're ready to start using Convex queries/mutations in the next phase.

Installed all the deps we'll need later: convex, @notifee/react-native (for notifications with custom sounds), expo-av (recording), expo-file-system, openai, and @expo/vector-icons for the icons.

**Roadblocks:**

The build kept failing with a "filename longer than 260 characters" error. Windows has this path length limit and our project path was way too deep (`C:\Users\AtheA\Desktop\Personal_Programs\voice-reminder\VoiceReminder\...`). Tried enabling long paths in registry but that needs a full restart. Just moved the whole project to `C:\Dev\VR` instead - much cleaner anyway.

React 19 caused peer dependency conflicts when installing packages. npm was complaining about version mismatches. Had to use `--legacy-peer-deps` flag on every install to get past it.

Notifee wasn't building because gradle couldn't find its packages. Turns out you need to add their maven repo manually. Added `maven { url "$rootDir/../node_modules/@notifee/react-native/android/libs" }` to `android/build.gradle`.

Last thing - the phone couldn't connect to Metro bundler. It was trying to hit localhost:8081 but that doesn't work from the phone. Since we're connected via USB anyway, used `adb reverse tcp:8081 tcp:8081` to tunnel the connection through USB. Worked right away after that.

**Result:** App builds and runs on Samsung SM_G955F. Both tabs work, navigation works, Convex is connected. Ready for Phase 2 (actual audio recording).

## Phase 2: Audio recording - (20:12)

**Status**: ✅ Recording works

**Intent:** Make the mic button actually record audio. Get the file URI so we can send it to Convex in Phase 3.

**What I did:**

Added expo-av plugin config to `app.json` with microphone permission. Created `lib/audio.ts` with helper functions - `requestMicrophonePermission()`, `startRecording()`, `stopRecording()`. Updated `record.tsx` to use these helpers and show a duration timer (mm:ss) while recording.

When you stop recording, it shows an alert with the file path and logs it to console. Tested by pulling the .m4a file from the phone via adb - plays back fine.

Files:
- `app.json:32-35` - expo-av plugin with mic permission
- `lib/audio.ts` - new file, recording helpers
- `app/(tabs)/record.tsx` - real recording logic, duration timer

**Notes:**
- expo-av is deprecated, will be removed in SDK 54. Replacement is `expo-audio`. Works fine for now.
- To pull recordings from device: copy to sdcard first with `run-as`, then `adb pull`. Direct pull from app cache gets permission denied.
