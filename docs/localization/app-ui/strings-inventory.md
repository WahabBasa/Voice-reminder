## Already in the user's language (no keys)

- **Reminder content.** The title, the spoken line (`description`), the heads-up line (`preDescription`) and the emoji are generated by the parse model in the language the user spoke (`convex/helpers.ts:69`). pt and es are voiced (`convex/languages.ts:55,58`, simba-3.0). They show in the list, the edit sheet, AlarmKit alert titles and notification titles. The English stand-in `"{title} in N minutes"` (`convex/helpers.ts:458`) is only used when the language is not multilingual-voiced, so English only.
- **Founder messages and feedback status notes.** These are free text typed by the founder in English. They can't be catalogued. Reply in the user's language by hand.

## Wiring recommendation

### 1. Runtime: `expo-localization` + `i18next` / `react-i18next` (+ ICU)

- **expo-localization is not installed.** `npm ls expo-localization` is empty, so it is not in node_modules or in any shipped binary. It is a native module, so adding it needs **one new EAS build**. After that, every JS string ships OTA.
- Use `i18next` + `react-i18next` with `i18next-icu`, so the catalog's ICU plurals and `{placeholders}` work as written. Each locale is a JSON file shaped like `strings-en.json` (`locales/en.json`, `pt-BR.json`, `es-MX.json`), bundled in JS so it can be updated OTA. A smaller option is `i18n-js` with its own pluralizer, but it does not read ICU message syntax, so the plural keys would need reshaping.
- Most strings are in `lib/` pure functions (`paywallContent`, `pendingCardContent`, `proCardContent`, `usageGate`, `voiceTake`, `time`, `scheduleDraft`, `remindersMembership`). Pass `t` in, or import a module-level `i18n.t`, rather than hooks. Tests pin the English output, so keep English as the default resource and the tests keep passing.
- Fix the concatenation spots while wiring: `"Remind me " + label.toLowerCase()` (`PendingTakeCard.tsx:260`); `patternLine` splitting `describeGridSubtitle` on `" · "` (`remindersMembership.ts:247`); the AI-consent prefix/link/suffix split (use `<link>` rich text with `Trans`); and the bold price run in the paywall caption (`<b>` rich text).

### 2. Native strings

- **Info.plist** (mic and AlarmKit permission prompts): add `expo.locales` in `app.json`, for example `{ "pt-BR": "./locales/ios/pt-BR.json", "es-MX": "./locales/ios/es-MX.json" }`, each holding `NSMicrophoneUsageDescription`, `NSAlarmKitUsageDescription` and optionally `CFBundleDisplayName`. Prebuild writes `<lang>.lproj/InfoPlist.strings`. **Needs a native build.** Fix the AlarmKit text while you're at it: it says "VoiceReminder", not "Remi" (`plugins/withAlarmKit.js:18`).
- **Declare the localizations** so iOS treats Remi as a pt/es app. Without that, iOS reports the app language as English and `getLocales()` / `Intl` resolve to `en-BR` / `en-MX`. The `expo.locales` lproj folders do this. Add `CFBundleLocalizations: ["en","pt-BR","es-MX"]` to `ios.infoPlist` to be explicit. iOS then also offers a per-app language picker under Settings › Remi › Language. Verify on the device.
- **AlarmKit "Later" / "Done"** (`plugins/withAlarmKit.js:626,630`, mirrored in `plugins/ios-src/VRAlarmIntents.swift:476,480`) are `LocalizedStringResource` literals, so a `Localizable.strings` / String Catalog in the app target would localize them with no Swift change. The better route is to pass `laterLabel` / `doneLabel` from JS in the schedule options, next to `title`, and store them in `VRAlarmStore`'s meta record. That way they follow the in-app language and can be updated OTA later. The "Later" intent re-schedules from Swift without JS (`VRAlarmIntents.swift`), so it must read the stored labels. Either route **needs a native build**. Watch the template-literal backtick trap in `withAlarmKit.js`.
- **Library defaults:** `react-native-timer-picker` (`TimesEditor.tsx:258`) shows its own English "Confirm"/"Cancel" because the props aren't passed. Pass `confirmButtonText` / `cancelButtonText`. JS only.

### 3. Dates, times, plurals

- Hermes in RN 0.81 / SDK 54 implements `Intl.DateTimeFormat`, `Intl.NumberFormat`, `Intl.Collator` and `toLocale*String` on iOS. It does **not** ship `Intl.PluralRules`, `RelativeTimeFormat`, `ListFormat` or `DisplayNames`. `lib/languageNames.ts:6` already assumes `DisplayNames` may be missing. Confirm with a one-line check on the device.
- Plurals: i18next v21+ needs `Intl.PluralRules`. Add `@formatjs/intl-pluralrules` (pure JS, OTA-safe) with en/pt/es locale data. pt-BR and es-MX are one/other (CLDR also has `many` for millions; irrelevant here).
- Replace the hand-built pieces with `Intl.DateTimeFormat(locale, …)`:
  - `formatClockTime`'s `"am"`/`"pm"` (`lib/time.ts:196`). es-MX writes "p.m.", and pt-BR is usually 24-hour.
  - `WEEKDAY_LABELS` (`scheduleDraft.ts:330`) and the `DAY_LETTERS` arrays (`WeekStrip.tsx:12`, `MonthSheet.tsx:8`, `DaySelector.tsx:5-11`). Use `{weekday:"short"|"narrow"}`.
  - The hard-coded `"en"` locale in `remindersMembership.ts:235`.
- The `weekday.*` keys stay in the catalog as a fallback only.
- Week start is hard-coded to Monday. Brazil and Mexico start the week on Sunday. That's a product call, not a string.
- Language names: `DisplayNames` is missing, so either ship the 35 `language.name.*` keys translated, or polyfill `@formatjs/intl-displaynames` (heavier).

### 4. Language selection

- Default: `getLocales()[0]` → pick `pt-BR` for any `pt-*`, `es-MX` for any `es-*` (es-ES users get Mexican Spanish until there's an es-ES file), everything else → `en`.
- OLD-109 (filed 2026-08-16: app-language selection, a first-run step plus a Settings row, feeding TTS routing) is the in-app override. If it ships, store the choice in `settingsStore`, and have it drive `i18n.changeLanguage` plus the AlarmKit labels passed from JS. Otherwise iOS's per-app language setting covers it once the localizations are declared.
- Separate setting: Settings › "Voice language" only offers Automatic / English / Arabic (`lib/deviceStt.ts:21`), though on-device STT locales include pt and es (`lib/spokenLanguage.ts:31`). Worth adding pt/es options when UI localization lands.

### 5. Effort estimate

| Step | Effort |
|---|---|
| i18n runtime + locale detection + PluralRules polyfill | 0.5 day |
| Replace ~330 literals across ~45 files with `t()`, incl. lib formatters + test updates | 2-3 days |
| Intl-based clock/weekday/date formatting | 0.5 day |
| Info.plist locales, CFBundleLocalizations, AlarmKit labels via JS (Swift + store) | 0.5-1 day |
| Translation of ~390 distinct strings x 2 locales (paywall disclosure needs care) | translator time |
| One native build, device test in pt-BR and es-MX (truncation in tabs, chips, CTA, AlarmKit buttons) | 0.5 day |

Total: about 4-5 dev days plus translation. Order: native build first (expo-localization, plist locales, AlarmKit label plumbing), then JS strings ship OTA as translations land.

Server: only `feedback.founder.defaultAbout` (`convex/feedback.ts:58`). It is stored on the feedback row when the founder sends a message. Better to store nothing and let the client show its own localized fallback, so the server stays language-free.
