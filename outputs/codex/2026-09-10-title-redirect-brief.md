## Fix 1 — reminder titles are too short to jog memory
User feedback: "take out my water bottle from the fridge at 6 pm" produced the title "Water bottle" — not enough context to remember what it was for.
Current rule (`convex/actions.ts:528`): `"title": "short title (2-4 words; must not begin with 'Reminder', 'It is time', 'Time to', or Arabic 'تذكير' / 'حان وقت' — the title names the thing, it never announces itself)"`. Language rules `:554-555`. The spoken line (`description`) is a separate field with its own rules (`:499-616`) — unchanged.
Plan: change the title rule to: 3-6 words; names the thing PLUS the distinguishing detail the user gave (place, person, subject, qualifier) — "Water bottle from the fridge", "Call mom about the flight", "Pay the electricity bill"; a bare object only when the user gave no context; no time/date words (those belong to the schedule); same no-self-announcing openers; Arabic symmetric. Update `__tests__/convex/parsePrompt.test.ts` expectations.
Questions: Q1 — where is the title rendered (reminder card, Days page rows, alarm/notification title, AlarmKit alarm title, live activity, edit sheet)? Any `numberOfLines`/truncation or a fixed-width layout that a 6-word title breaks, especially the Days page rows and the AlarmKit alert (`plugins/ios-src/*.swift`, `lib/notifications.ts`)? Q2 — anything else that assumes 2-4 words (prompt-cache tests, fixture snapshots, `convex/helpers.ts` shared rule text, `parseUsage` token budgets)? Q3 — the typed path (`processTypedReminder`) uses the same prompt — any reason a typed reminder should keep the shorter rule?

## Fix 2 — a voice take started from the Days page leaves the user on Days, so they never see the new card
Facts: pages are `PAGE_TODAY=0` (the Reminders list) / `PAGE_DAYS=1` / settings (`app/index.tsx:125-126`, state `:244`, tab→page `:1713`). `DaysPage` is mounted with `active={page === PAGE_DAYS}` (`:1864-1870`). The landed handler is `onTakeImported` (`:1356-1362`: LayoutAnimation, `setImportedCardId(created[0].id)` which highlights/scrolls the new card on the Reminders list). The recording overlay is global (works from any page). Take lands ~4-7 s after the stop tap; on relaunch, `lib/takeReconcile.ts` lands it later via the same handler.
Plan options — Claude leans A: 
- A. Switch to the Reminders page at the STOP TAP (when the pending take/card is created), so the user watches the pending card resolve where it lives. 
- B. Switch only when the take lands (in `onTakeImported`, `if (page === PAGE_DAYS) setPage(PAGE_TODAY)` before highlighting).
