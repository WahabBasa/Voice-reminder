## Plan
1. **Snag report on a failed take** — the failed card gets a "Tell me what happened" tap: optional one-line text, Send. Auto-attaches creationId, errorKind, server errorCode, transcript if any, perf, build number, update id, iOS version, deviceId.
2. **"This reminder came out wrong"** row in the edit sheet — sends the job transcript (what was heard), what the parse produced (title / spoken line / schedule), and the user's edits if they changed fields before reporting. This is the parse-quality signal.
3. **Settings feedback box** with rotating placeholder prompts in the Stripe spirit but softened for a consumer app ("What's the most annoying thing about Remi?", "Which reminder came out wrong last?"), optional email for a reply.
4. **Automatic snag alerts, no user action**: failed takes (server/unparseable) and STT fallbacks are also captured as Sentry events with the same context bundle, so the founder sees them even when the user says nothing. Sentry alert rule → email within minutes.
5. **Transport + offline**: a local outbox in AsyncStorage (`lib/feedbackOutbox.ts`), items get an id at creation, UI immediately shows "Sent" or "Will send when you're back online"; flushed on app foreground and on reconnect; delivered via a Convex mutation `feedback.submit` (new `feedback` table, idempotent on item id), and a Convex action forwards each item to the founder through a webhook URL in a Convex env var (Slack / Telegram / Discord incoming webhook) so it lands on the phone within a minute. No email infra.
6. **Closing the loop (phase 2, optional)**: the founder types a reply into the `feedback` row in the Convex dashboard; the app watches this device's feedback rows and shows the reply as a banner on next open ("From Abdul: fixed it, try again"). Uses existing Convex reactivity, no push infra.
