**(1) Factual corrections**

- **System dictation quality does not establish SpeechTranscriber quality.** Apple identifies `DictationTranscriber` as using system dictation/on-device `SFSpeechRecognizer` models; `SpeechTranscriber` uses a different model. Test the fridge recording against both before choosing. [Apple](https://developer.apple.com/documentation/speech/dictationtranscriber)
- **“Retry/reconcile untouched” is incorrect.** `beginAndSubscribe` explicitly fails without `audioStorageId` ([lib/takeReconcile.ts:420](C:/Dev/VR/lib/takeReconcile.ts:420)). Persist the device transcript and selected source, and make rebegin/recovery accept them.
- **The schema already has optional `transcript` and `audioStorageId`.** Change `begin`’s validation and worker routing; those two schema fields are not new. [convex/schema.ts:216](C:/Dev/VR/convex/schema.ts:216)
- **Do not route solely on `job.transcript` presence.** Cloud jobs also acquire transcripts, and retry preserves them—even when replacing audio. Use an explicit source; otherwise replacement audio can be ignored. [convex/creationJobs.ts:622](C:/Dev/VR/convex/creationJobs.ts:622)

**(2) Q1–Q6**

- **Q1 — File/API:** Yes: `analyzeSequence(from: AVAudioFile)` is supported. Read results concurrently, call `finalizeAndFinish(through:)`, then await the accumulated final transcript. File-read completion alone is insufficient. [Apple](https://developer.apple.com/documentation/speech/speechanalyzer/analyzesequence(from:))
- **Q1 — Permissions:** SpeechAnalyzer modules do **not** require `SFSpeechRecognizer.requestAuthorization` or `NSSpeechRecognitionUsageDescription`; recording still requires microphone permission. Apple explicitly limits that speech-authorization procedure to `SFSpeechRecognizer`. [Apple](https://developer.apple.com/documentation/speech/asking-permission-to-use-speech-recognition)
- **Q1 — Assets:** No `reserve` + `allocate` sequence. Current API: `assetInstallationRequest(supporting:)` → `downloadAndInstall()`; reservations happen automatically if needed, with explicit `reserve(locale:)` available. Installation persists across launches, but recheck readiness. Apple provides no fixed English/Arabic download sizes here. [Apple](https://developer.apple.com/documentation/speech/assetinventory)
- **Q1 — Format/speed:** Keep the m4a for the file-based trial; `AVAudioFile` decodes compressed audio. For manually supplied buffers, convert to a compatible PCM format using `bestAvailableAudioFormat` and `AVAudioConverter`; do not assume 16 kHz is the model format. I could verify file support, but not an explicit automatic-resampling guarantee for this exact input. No verified Apple A14/5–10-second timing supports a numerical promise. [Apple sample](https://developer.apple.com/videos/play/wwdc2025/277/)
- **Q2 — Arabic:** I could not establish an authoritative fixed Arabic region list for iOS 26.6. Resolve the requested locale with `supportedLocale(equivalentTo:)`, check `isAvailable`, then installed assets; return the resolved identifier. Unsupported/unready → cloud is sensible for phase one. Do not hard-code “Arabic unsupported.”
- **Q2 — Alternative:** `DictationTranscriber` is the missing native fallback candidate. Legacy `SFSpeechRecognizer` only honors `requiresOnDeviceRecognition` when `supportsOnDeviceRecognition` is true; the flag cannot manufacture Arabic support. [Apple](https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition)
- **Q3:** Agree with file-based phase one, **not the <500 ms assumption**. Measure cold/warm stop→final and stop→card on the actual iPhone 12. Asset download is not model warm-up: `prepareToAnalyze(in:)` can preheat during recording. Streaming becomes justified if measured post-stop work remains material. [Apple](https://developer.apple.com/documentation/speech/speechanalyzer)
- **Q3 — Budget:** You remove upload plus roughly 1.14 s of storage-get/STT, then add device transcription. Parse, job pickup, and commit remain. A 3 s timeout followed by cloud can make fallback approximately 3 s slower than today.
- **Q4:** No production shadow-upload machinery for week one. Compare a small developer/TestFlight corpus through both engines and inspect reminder dates/times as well as words. Background uploads need ownership, cleanup, and retention handling; uploading alone produces no comparison transcript.
- **Q5:** A single locale is not an automatic bilingual mode. I found no documented iOS 26 SpeechTranscriber audio-language autodetection contract. Treat English insertions in Arabic—and vice versa—as accuracy tests; a plausible wrong transcript will not trigger empty/error fallback. Apple’s API selects a transcription locale. [Apple](https://developer.apple.com/videos/play/wwdc2025/277/)
- **Q6:** File analysis needs no microphone tap or recording-category change. Keep VRSpeech out of AVAudioSession management and start after unload resolves. The deferred restore should not affect reading a finalized file; that is an architectural inference, not a device-tested guarantee. [lib/audio.ts:191](C:/Dev/VR/lib/audio.ts:191)

**(3) Five real edge cases**

- **First take/model unavailable:** Preparation may still be downloading or fail. Use cloud immediately unless ready; never spend the 3 s transcription budget downloading.
- **Timeout/cancel followed by late native completion:** Cancel native analysis and suppress late results. One client operation must select the source and call `begin`; the existing server deduplication preserves whichever request arrived first.
- **App closes or network drops before `begin`:** Persist transcript, source, locale, and original date/time context before submission. Reconcile must resume without requiring an upload.
- **Silence, clipped speech, or mixed-language wrong time:** Finalize and concatenate all segments; trim empty output. Keep the existing correction/retry experience because nonempty text is not proof of correctness.
- **Longer take/cold model:** A fixed 3 s cap may systematically send otherwise successful takes to cloud. Choose the cap from measured clip-length and cold/warm results.
