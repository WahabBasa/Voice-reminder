## Simplified plan
Backend (Convex, new table `feedback`): `{clientId (uuid idempotency key), deviceId, text (1..2000), createdAt, receivedAt, context?: any (≤8 KB), status: "received"|"looking"|"fixed", note?: string, updatedAt}`; indexes by_device [deviceId, createdAt], by_client [deviceId, clientId]. `feedback.submit` mutation (idempotent on deviceId+clientId; schedules an internal action), `feedback.listForDevice` query (newest 50, no context/deviceId), `feedback.setStatus` internal mutation the founder runs from the dashboard function runner ({id, status, note?} → bumps updatedAt), `feedback.notify` internal action that emails the founder via the Resend REST API (env RESEND_API_KEY + FEEDBACK_EMAIL_TO already set; from onboarding@resend.dev; plain-text body with the text + a whitelisted context block; never deviceId; no retries).
Client: one composer sheet (text box + Send; "Includes this reminder's details" line when opened from a reminder) reachable from (a) a Settings row "Send feedback", (b) the failed-take card, (c) the reminder edit sheet ("Report a problem" — does not save or discard the user's unsaved edits). No email field. Context attached automatically: kind, reminder title/spoken line/schedule (from the store row — current values), errorKind/serverErrorCode/creationId/sttSource for failed takes, buildNumber, updateId, iOS version, timezone, local time. Durable AsyncStorage outbox (`lib/feedbackOutbox.ts`): persist first → "Saved. Sends next time Remi is online." → flush on app foreground/reconnect/after submit → "Sent" only after the mutation returns. Status view: Settings → "Your feedback" list from `listForDevice` (status chip Received / Looking into it / Fixed + note). On app open, if any item's `updatedAt` is newer than the locally stored last-seen timestamp, show a one-line banner "Your feedback was updated" that opens the list; tapping/opening marks it seen (local).
